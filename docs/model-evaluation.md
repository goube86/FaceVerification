# Model Evaluation and Threshold Calibration

The default `MatchThreshold` and `NonMatchThreshold` are starting values for integration, not a production accuracy claim. Do not copy a published threshold without validating the exact model file, alignment, preprocessing, population, capture channel, and operational cost.

Build a consented, access-controlled evaluation set representing the deployment population. Include genuine pairs and impostor pairs across supported cameras, compression, resolution, lighting, exposure, blur, age intervals, expression, occlusion, pose, skin tones, and relevant demographic groups. Keep evaluation identities separate from any tuning identities and define retention/deletion rules.

For each candidate threshold measure:

- **False Match Rate (FMR):** impostor comparisons incorrectly accepted.
- **False Non-Match Rate (FNMR):** genuine comparisons incorrectly rejected.
- Coverage and error rates inside each quality, device, lighting, age, pose, and demographic slice.

Choose `MatchThreshold` from the maximum tolerable FMR and `NonMatchThreshold` from the maximum tolerable FNMR. Values between them form the `Inconclusive` zone and should trigger a safe retry or reviewed alternative flow. Report confidence intervals and sample counts; aggregate accuracy can hide harmful slice-level differences.

Repeat evaluation after changing model bytes, OpenCV/ONNX versions, detector confidence, alignment, image normalization, quality rules, cameras, or population. Record manifests and hashes with every report.

## Local acceptance matrix

No biometric fixtures are committed. Place approved local files in `tests/FaceVerification.ModelTests/Fixtures/Local` using the names documented in that directory, start the API in `Development`, and run:

```powershell
pwsh ./scripts/evaluate-faces.ps1 `
  -FixturesPath ./tests/FaceVerification.ModelTests/Fixtures/Local `
  -BaseUrl http://localhost:5276 `
  -OutputCsv ./face-verification-results.csv
```

The ignored CSV records the native cosine similarity, applied thresholds, quality scores, model version, decisions, and timings for the A/A, A/B, A/C, A/D, B/C, no-face, and multiple-face cases. Preserve aggregate evaluation results only under the project's privacy and retention policy; do not commit images or identifiable biometric data.

To replace SFace, implement `IFaceEmbeddingProvider`, document its exact input layout/color/normalization and embedding size, add an official-source manifest/license/checksum, register the provider in Infrastructure, and recalibrate all thresholds. Domain, Application use cases, and HTTP endpoints must remain unchanged. During a model transition, never compare embeddings generated by different model versions.
